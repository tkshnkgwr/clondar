# コントリビューションガイドライン (CONTRIBUTING.md) - Clondar

[English Version](../en/CONTRIBUTING.md) | **日本語版**

`Clondar` プロジェクトへの貢献に関心をお寄せいただき、誠にありがとうございます！  
バグの報告、新機能の提案、およびプルリクエスト（PR）を提出される際は、以下のガイドラインをご参照ください。

---

## 1. 開発方針・基本原則

コントリビューションを行う際は、プロジェクトの設計思想に沿って以下の基本原則を遵守してください。

1. **ローカルファースト / 完全オフライン動作の保証**:
   - アプリはインターネット接続なしで完全に動作するよう設計されています。外部 CDN へのリンクやネットワーク通信への依存を追加しないでください。
2. **ビジュアルの統一性（枠なし・透過・影なし）**:
   - ウィンドウの枠線や OS 標準のドロップシャドウを排除した「極限のミニマリズム」デザインを維持してください。また文字化け（豆腐）を防ぐためアイコンには `src/icons.rs` のベクター描画を使用してください。
3. **日英ドキュメントの同期保守**:
   - 仕様変更や機能追加を行った場合は、`docs/ja/` および `docs/en/` 双方の関連ドキュメントを同期更新してください。

---

## 2. 開発環境のセットアップ

ビルドおよび実行には **Rust (1.96.0 以上推奨, MSVC ターゲット)** が必要です（`common_lib` を同時編集する場合は同じ親ディレクトリに配置してください）。

1. **リポジトリのクローン**:
   ```bash
   git clone https://github.com/tkshnkgwr/clondar.git
   git clone https://github.com/tkshnkgwr/common_lib.git
   cd clondar
   ```
2. **開発モードで起動**:
   ```bash
   cargo run
   ```

---

## 3. コミット・プルリクエストの手順

### コミットメッセージ規約
変更内容が明確に伝わるプレフィックス（Conventional Commits 形式等）を推奨します：

- `feat:` 新機能の追加
- `fix:` バグの修正
- `docs:` ドキュメントの更新
- `refactor:` コードのリファクタリング
- `perf:` パフォーマンス・メモリ改善
- `test:` テストの追加・修正
- `chore:` ビルド設定・スクリプトの更新

### 提出前チェックリスト
プルリクエストを作成する前に、ローカル環境で以下のコマンドがすべてエラーおよび警告ゼロで完了することを確認してください：

- [ ] `cargo fmt --check` (コードフォーマット規約準拠)
- [ ] `cargo clippy --all-targets -- -D warnings` (Clippy 静的解析パス)
- [ ] `cargo test` (単体テストパス)
- [ ] `cargo doc --no-deps --document-private-items` (RustDoc ビルド正常完了)
